# 强制刷新误报多页占用修复 · 2026-11-03

## 根因和证据

旧前端为每次加载生成新的 owner，服务端仍保留旧 owner 的十秒写租约。pagehide 处理先等待进度提交和计时请求，最后才释放租约；文档销毁时异步链可能被中断，释放请求没有发出。新文档没有交接凭据，因此被当作第二个页面拦截。

本机原服务日志 `reports/server-v2-20261103-064945.err.log` 显示：07:29:46 最后一次计时成功，07:29:47 刷新后开始进入请求409，直到07:29:56仍在冲突；期间没有释放请求。此前仅提供手动重连，没有解决卸载请求丢失，也未合并并行重连。

## 修复行为

- 新增 `static/core/browser-activity.mjs`，使用同源独占 Web Lock 判断旧活动文档是否仍在。拿到浏览器锁后才读取本地交接凭据；真实仍在活动的另一页不能取得锁。依据 [W3C Web Locks](https://www.w3.org/TR/web-locks/) 的文档卸载清理机制，文档销毁后由浏览器释放活动锁，不依赖最后一个网络请求完成。
- 服务端同时验证 previousOwner 和 resumeToken，凭据匹配才立即交接并轮换 token。旧 token 不能继续计时或写记录，旧页迟到的释放不能影响新租约。没有正确凭据的请求仍被拦截。
- 卸载时同步入队末段前台时间和可保存进度，立即发出 keepalive 释放请求，不再等待其他网络请求。退役文档禁止重新申请租约。尚待确认的原子操作保留在待提交队列，不用旧进度覆盖已确认回答。
- 重连与自动恢复合并。旧版遗留租约到期后自动恢复，浏览器锁暂未清理时自动重试；真正的另一页仍在活动时持续互斥。恢复返回首页，不自动开始活动或播放声音。浏览器不支持 Web Locks 或本地存储不可用时，回退到租约到期恢复。
- 从浏览器往返缓存恢复的旧文档重新加载，避免继续使用已退役的存储对象。前端入口已更新版本查询参数。

本轮不清理家庭数据库、不重置时间、进度、历史或贴纸，也不取消多页互斥。
